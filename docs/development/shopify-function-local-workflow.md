# Shopify Discount Function Local Workflow

This repository includes a Rust-based Shopify Function at `extensions/loopdesk-discount-function`.
Local `cargo` and Shopify CLI commands can create or update files that are not meant to be committed during routine development.
Clean these artifacts before pulling, rebasing, or opening a hygiene-only pull request.

## Commands

Run the function tests from the repository root:

```bash
cargo test --manifest-path extensions/loopdesk-discount-function/Cargo.toml
```

Build the function from the repository root:

```bash
cargo build --manifest-path extensions/loopdesk-discount-function/Cargo.toml --target=wasm32-unknown-unknown --release
```

Deploy with the Shopify CLI when intentionally publishing extension configuration and build output:

```bash
shopify app deploy
```

## Expected generated or local files

The following files and directories may appear after local Rust or Shopify CLI workflows:

- `extensions/loopdesk-discount-function/target/` — Rust build output. This is ignored and should not be committed.
- `extensions/loopdesk-discount-function/Cargo.lock` — local lockfile for this function crate when generated by Cargo. It is ignored unless the team intentionally changes policy and tracks it.
- `extensions/loopdesk-discount-function/shopify.extension.toml` — real Shopify extension configuration. This file is tracked and must not be globally ignored.

## Cargo.lock policy

`extensions/loopdesk-discount-function/Cargo.lock` is treated as a local generated artifact for this project because it is not currently tracked in git and this workflow does not change Rust dependencies.
Do not commit it during hygiene or routine build/test work.

If a future dependency change requires committing a lockfile, make that decision in the dependency-change PR, remove or narrow the ignore rule, and explain why the lockfile is now intentionally tracked.

## Shopify extension TOML churn

`extensions/loopdesk-discount-function/shopify.extension.toml` contains real extension configuration, including the extension target, build command, WASM path, and API version.
Shopify CLI deploy workflows may rewrite local fields or generated identifiers in this file.
Restore generated/local-only changes before pull, rebase, or commit unless the extension configuration change is intentional.

A safer long-term option may be to isolate environment-specific Shopify CLI state outside the tracked TOML file if Shopify supports that for the generated field in question. Do not add `shopify.extension.toml` to `.gitignore`, and do not use `git update-index --assume-unchanged` as a team workflow because it can hide real configuration changes.

## Cleanup before pull, rebase, or commit

PowerShell cleanup command for Windows developers:

```powershell
git restore extensions/loopdesk-discount-function/shopify.extension.toml

if (Test-Path extensions\loopdesk-discount-function\target) {
  Remove-Item -Recurse -Force extensions\loopdesk-discount-function\target
}

if (Test-Path extensions\loopdesk-discount-function\Cargo.lock) {
  Remove-Item -Force extensions\loopdesk-discount-function\Cargo.lock
}

git status
```

This repository also provides a helper script:

```powershell
.\scripts\clean-shopify-function-artifacts.ps1
```

The helper restores `shopify.extension.toml`, removes `target/`, removes `Cargo.lock` only when it is untracked, and prints `git status` at the end.

## Why rebase pulls fail with generated files

The team uses `git pull --rebase` workflows. Rebase requires a clean working tree so Git can safely replay local commits on top of upstream changes.
Generated files, untracked lockfiles, build directories, or local Shopify CLI TOML rewrites can make the working tree dirty and block the pull even when no product logic changed.
